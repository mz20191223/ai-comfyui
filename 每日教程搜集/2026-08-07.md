## 1. 新发现：教程 / 工具 / 工作流

### 🆕 A. LTX 2.3 20宫格漫剧工作流（多源集中报道，本地低显存）—— 直接命中「最终：漫剧」
- **来源**：idc.madlive.cn、CSDN（weixin_30998797 / weixin_29483277）、掘金（juejin 7626197125010931722）、intelliparadigm、ipipp；B站工作流 JSON 反爬未直采（UP主「AI代码侠土豆」，夸克网盘 `pan.quark.cn/s/2bbad26833fc`）。
- **核心要点**：
  - 流程：剧本 → LLM 拆 20 个分镜 → 用 Flux / NanoBanana / Wan2.2 生成**一张 20 宫格分镜大图**（开 IPAdapter + FaceID 锁脸/衣）→ 喂给 **LTX 2.3 I2V** + Qwen3-TTS 对白音频 → 输出 ~60 秒（~1440 帧）连贯漫剧 MP4。
  - 一致性关键：先备**多角度 turnaround 参考图**，让主角在 20 格里不崩；提示词加 `comic panel layout, manga style, same character consistent face and clothes`。
  - 显存：**FP4 量化（AWQ，官方 `ltx23_fp4_calibrator.py`）仅 14.2GB（4090）**，画质损失 <3%（SSIM）；宣称最低 8GB 可跑 720p。FP16/BF16/INT8 在 4090 上分别 32.6/31.8/19.3GB（INT8 有色带/锯齿崩皮）。
  - Motion Strength 中低值保「漫画分镜感」；对话场景适合大段音画同步。
- **适用场景**：**最终漫剧（动态漫画风）的本地直接路径**；亦作多镜叙事素材。复用我们现有 LTX 2.3 基线 + Qwen 出图线，几乎零新增基础设施。
- **与我们基线的关系**：是 07-27「Grid Method」的**成熟落地版**（不再是概念，已有可下载 JSON/网盘 + 多源实测）。⚠️ 属「动态漫画」动画化，**非真 3D 动作连贯**；T4 15.9GB 跑 FP4 20 格或勉强（需实测），4090/24GB 更顺。

### 🆕 B. 阿里云 Qwen 本地 AI 漫剧全流程（三重锁定，零成本）—— 验证出图线 A 强化方案
- **来源**：阿里云开发者社区 `developer.aliyun.com/article/1748612`
- **核心要点**：
  - **三重锁定**：IPAdapter + FaceID + StoryDiffusion（上传 2–4 张正/侧/多表情参考 + Impact-Pack 人脸精修 + OpenPose 姿态控制），跨镜头彻底锁脸/身形/服饰。
  - 出图线：GGUF 量化 **Qwen-Image 2512** 批量出统一光影分镜原画（8G 显存可跑）；IF_AI_tools 自动读 JSON 分镜转提示词。
  - 视频线：AnimateDiff-Evolved（轻量微动）/ Wan2.2 / LTX2.3（长时序对话/转身/互动）三选一。
  - 本地配音：Qwen3-TTS + 音画同步节点；或导出剪映加字幕/BGM/转场，单集成片 30–60 分钟。
- **适用场景**：**出图线 A 锁角色出图 + 漫剧编排**的零成本闭环。
- **与我们基线的关系**：独立第三方印证了「Qwen 2512 + 三重锁定」路线可行且便宜；StoryDiffusion 补强跨镜一致，可与我们的 Qwen 出图线合并采用。

### 🆕 C. MiniMax H3 落地细化：API 定价 + NVFP4 权重 + 能力边界（重要，修正/补全 08-05）
- **来源**：网易（dy/L3G0C0L6 / L3FMU9PA）、新浪/智东西、CSDN（xyghehehehe 163430919）、掘金部署实录（7669726629519360015）、docs.comfy.org、runcomfy
- **核心要点（精确化）**：
  - **能力边界**：输出 **4–15 秒**（非 30 秒）、原生 **768p 短边**（最大 768×1344）、最高 2K 但 **2K 模块（H3-Regenerate-2K）仅 API、未开源**、24fps、32kHz 原生立体声、稳定 11 语言；**Ref2VA 全参考最多 9 图 + 3 视频 + 3 音频**（合计 ≤12）。
  - **AA 榜单**：有声视频编辑全球第一（Elo 1130），文生/图生居第一梯队。
  - **本地权重 NVFP4 剪枝版**：`ref2va_pruned_nvfp4`(12.5G) + `fl2va_pruned_nvfp4`(12.5G) + `qwen3vl_32b_nvfp4_awq`(15G) + VAE ≈ **34G**（int8 约 40G）；2K 仅 API。ComfyUI 原生 PR #15224，官方模板 I2V/T2V/R2V JSON 可直接拖入；**R2V 用 ref2va 权重，与 T2V/I2V 的 fl2va 不同**（切换仅改 UNETLoader 下拉）。
  - **💰 API 定价（官方）**：768p **¥0.23/秒**、2K **¥0.4/秒**（约主流旗舰 1/3）——远低于 Seedance 2.5 估算 ¥1.5–3/秒。
- **适用场景**：第一步单角色带情节（多为 <15s 短视频）的**廉价云端验证渠道**——原生立体声 + 全参考锁角色 + ¥0.23/s；本地部署则待 ≥24GB GPU。
- **与我们基线的关系**：把 **H3-API 提为「单镜验证」低成本并列项**（vs Seedance 2.5 时长更长但更贵；vs Digen 质量更高）。⚠️ 上限 15s/768p，长叙事/4K 仍用 Seedance。本地主线仍待换大显存（34G NVFP4）。

### 🆕 D. dredyson 8GB 显存身份漂移修复方法论（强相关、零训练）—— 直接增强我们 LTX/T4 管线
- **来源**：dredyson.com（两篇，2026-08，8GB VRAM 实测）
- **核心要点（可照搬进 LTX 主线，无需训练 LoRA）**：
  1. **关键帧锁脸嵌入**：IPAdapter-FaceID 权重 **0.8** 作用在每一关键帧（给模型一个忽略不掉的人脸锚，生成即失败早退好过静默漂移）。
  2. **相似度校验闸 0.6**（FaceNet 类）：低于 0.6 视为漂移；实测使一致率从 ~30% 提到 **>85%**。（阈值 0.9 误杀好帧、0.3 放过明显漂移，0.6 为甜点）
  3. **末帧 inpaint 串联**：每段末帧作下一段 `init_image`，**denoise 0.25–0.3**（>0.5≈重生成、<0.25 不响应新 prompt）；与 IPAdapter-FaceID 双重保险。
  4. **首尾帧（FLF）控制**做转场：已知起止态让模型补中间运动（边界条件固定）。
  5. **人物圣经（character bible）**复用：固定姿态/表情参考图库跨项目复用。
- **适用场景**：**第一步 桃子单角色带情节**的本地一致性强化的**最高性价比加法**（无新增基础设施、无训练）。
- **与我们基线的关系**：与既有 **10S Likeness Guide / IC-LoRA-Ingredients** 互补（参考锚 + 时间携带 + 闸值三重保险），直接缓解 LTX「单 pass 必漂」的已知痛点。

## 3. 及时调整建议

1. **单镜验证渠道：在 Seedance 2.5 之外，新增 H3-API 作廉价并列项**。理由：H3 原生立体声 + 全参考锁角色 + **¥0.23/s（768p）** 远低于 Seedance（¥1.5–3/s），上限 15s/768p 恰够桃子带情节短视频；长叙事/4K 用 Seedance。替换/补充的是「基线 Digen 单镜验证」这环，本地 LTX 主线与 Qwen 出图线不动。风险：第三方 API 的 IP 出境（与即梦/火山既有口径一致，仅作验证/补充）。

2. **出图线 A 修正：弃用「待验证的 Qwen-Character-2512 LoRA」**。检索（HuggingFace/Civitai）未见干净独立可下载版本——CSDN 描述的是某镜像内置工作流；现有同类为 `a3xrfgb/Qwen-2512-portrait`（身份保留向 LoRA，HF 可下）或各类角色/风格 LoRA。改用 **Qwen-Image-Edit-2512 原生多参考**（`TextEncodeQwenImageEditPlus` 多图 conditioning）为主、可选叠加 `a3xrfgb/Qwen-2512-portrait`。零额外风险。

3. **本地 LTX 主线一致性加法：采纳 dredyson 工程纪律**。在既有 10S Likeness Guide / IC-LoRA-Ingredients 之上叠加：末帧 inpaint 串联（denoise 0.25–0.3）+ IPAdapter-FaceID 0.8 + 0.6 相似度闸 + FLF 转场。零训练、零新基础设施，最贴合 T4 当前约束，直接缓解 LTX 漂移。

4. **漫剧预研：把 LTX 2.3 20宫格工作流正式列为「最终漫剧」本地直接路径**。复用现有 LTX 基线 + Qwen 出图，FP4 14.2GB/4090；属动态漫画风（非真 3D 动作），第一步真 3D 叙事仍走 LTX I2V + 末帧串联。

5. **本地可控主线暂不替换 LTX 2.3**。T4 15.9GB 下 MiniMax H3（NVFP4 ≈34G）/ BindWeave（Wan 14B, 24GB+）/ Wan 3.0（24GB+）均无法本地跑；H3 本地仅作评估。换 A10/4090 后，主线候选优先级维持 **MiniMax H3（原生音频带情节）> BindWeave（像素级多图参考）> Wan 3.0**。
