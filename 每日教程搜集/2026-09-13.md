## 1. 新发现：教程 / 工具 / 工作流

### 1.1 dredyson — 锚帧 + IPAdapter FaceID + 首尾帧，根治 AI 视频"换脸漂移"（⭐ 今日头条，直接服务第一步）
- 来源：[dredyson.com — Fix AI Video Face Drift Forever](https://dredyson.com/fix-ai-video-face-drift-forever-a-beginners-step-by-step-guide-to-temporal-consistency-in-comfyui-using-ipadapter-anchor-frames-and-first-last-frame-control-tested-on-8gb-vram)（**实测 8GB VRAM 可跑**，含 5 阶段完整工作流与常见误区）
- 核心要点（一套经实测、可直接抄的"保一致"动作，与我们的 LTX I2V 主线天然衔接）：
  1. **锚帧（Anchor Frames / Character Bible）是生产锚点，不是"好看的图"**：先产 4–5 张角色圣经图（正面/侧面/表情/各镜姿态），逐一比对"像不像同一个人"，不像就重出——作者花 90 分钟定圣经，省了约 10 小时返工。
  2. **I2V 低 denoise 接力**：每段用本镜锚帧作首帧，I2V denoise 压到 **0.25–0.5**（只做轻微运动），段末帧 inspect，漂移即 inpaint 修复，再存为下一段 handoff 图。
  3. **短片段 + 显式交接**：每段 24–48 帧（≈1–2s@24fps），绝不整段长生成；拼接在剪辑软件做，逐段边界查残漂。
  4. **IPAdapter FaceID（weight 0.8）作安全网**：给每个角色一张正脸参考喂 FaceID，不依赖纯文本保人。
  5. **明确误区（对我们 SOP 极有价值）**：①"要一致必须训 LoRA"是错的——简单场景架构（锚帧+FaceID）远重要于训练；②"更好的提示词能保一致"是错的——模型段间无记忆，必须给视觉锚点；③"多 LoRA=更好"是错的——额外 LoRA 互相打架；④"整段一次生成"是错的——每多一秒无锚生成就是多一秒漂移积累。
- 适用场景：**桃子第一步零成本纪律升级首选**。可直接套进我们「Qwen-Image-Edit 出角色圣经 → LTX I2V 低 denoise 接力」主线，把 C98/C43 从"原则"变成"可操作步骤"。

### 1.2 SkyReels-V3（GitHub 开源权重，⭐ 今日最该入库，直接服务"多角色 + 长叙事 + 对白"）
- 来源：[github.com/SkyworkAI/SkyReels-V3](https://github.com/SkyworkAI/SkyReels-V3)（SkyworkAI 官方仓库，README + 推理代码 + 权重已发布；模型在 HuggingFace / ModelScope）
- 核心能力（三项原生，正是我们"下一步/最终"的硬需求）：
  1. **Reference-to-Video（多主体参考生视频）**：输入 **1–4 张参考图**（角色肖像 / 物体 / 背景场景），按文本指令生成连贯视频，**保角色身份 + 物体 + 背景一致**；多比例 1:1 / 3:4 / 4:3 / 16:9 / 9:16；推荐 5s@720p。→ 这正是"下一步多角色"比 LTX（单主体优先）更对口的能力，且是**本地开源权重**（无 IP/出境风险，资产在自己机器）。
  2. **Video Extension（视频续写）**：输入已有片段续写后续场景，5–30s 可调；支持**单镜续接 + 多镜切换（5 种转场）**。→ 补 LTX 20s 时长上限短板（与 C108 LongCat 并列长叙事本地候选）。
  3. **Talking Avatar（音频驱动口播）**：单张肖像 + 音频（**≤200s**）生成说话头像。→ 与 C79 Wan2.2-S2V / C88 InfiniteTalk 同属"对白/口播驱动"路线，本地开源备选。
- 硬件：模型 14B-720P（Ref2V / Extension）、19B-720P（Talking Avatar）；`<24GB` 卡可用 `--low_vram`（**FP8 权重量化 + block offload**），并降分辨率到 540P/480P。→ **A10 24GB 走 low_vram 可跑**，但 14B 量级预期比 LTX 慢、需 offload 耐心。
- 许可：仓库含 `LICENSE.txt`（开源权重，具体条款以仓库 LICENSE.txt 为准，非明确 Apache；请以官方仓库为准）。
- 适用场景：下一步多角色（本地、保身份+背景）、长叙事续写、对白口播——列为**强待验证候选**，不进当前第一步主线。

### 1.3 Seedance 2.5 参考比例规则 + 音频符号语法（ByteDance 官方实践指南坐实，细化云快验 SOP）
- 来源：[tryonr.com — Seedance 2.5 Prompt Guide (Official Formula)](https://tryonr.com/blog/seedance-2-5-prompt-guide)（直引 ByteDance 官方 practice guide）
- 核心要点（可直接写进 C56/C66/C93 的 Seedance SOP）：
  1. **参考比例规则（Reference Ratio Rule）**：Seedance 2.5 虽支持 50 参考，但**非越多越好**——ByteDance 实测超过阈值反而稀释特征、加噪声。单主体参考图 **≤5 张最稳、6–10 勉强、>8 开始不稳**；**视频/音频参考各 5–10s 最佳**（2s 信息不足、30s 稀释）。超出预算时删减顺序：**核心角色 > 关键道具 > 场景环境 > 整体风格**（风格最先砍，正好反直觉）。
  2. **音频符号语法（官方）**：音乐 `( )`、音效、对白 `{ }`、字幕 `【 】`；可显式关音（`No background music.` / `No subtitles.` / `No sound at all.`）；非英语对白先写语言名再写 `{台词}`。→ 比我们之前口头说的"prompt 里写声音"更精确，可直接用。
  3. **负向提示可用**：官方室内设计示例以整段 Negative 锁定布局/物体/机位/无 flickering。→ 强化 C83/C93 验收。
- 适用场景：第一步云快验（Seedance 2.5 R2V）的可操作化细化，零成本。

### 1.4 可灵 Kling 3.0 深度实测：对白标注语法 + 角色"元素"系统 + 定价真相（细化多角色/带情节云侧）
- 来源：[genra.ai — Kling 3.0 完整指南](https://genra.ai/zh/blog/kling-3-0-complete-guide) · [acceptprompt/sohu — Kling 3.0 提示词指南](https://www.sohu.com/a/1036042907_121123989)（**微信公众号/小红书原文反爬，需用户手动发链接**；此为 sohu 转载镜像）
- 核心要点（把 C77/C95/C105 变成可落地的写法与成本预期）：
  1. **对白说话人显式标注**：`[说话人:男] "我们得走了。"` / `[说话人:女] "去哪?"`；多角色必须显式标，否则说话人混淆。→ 直接服务"带情节+对白"。
  2. **角色"元素"系统（Elements / Feature Library）**：上传参考图或 **3–8s 参考视频**锁定角色外貌+嗓音，运镜中保身份；同画面 3 人以上不混脸；国内测评一致率约 **80%**（偶有肤色/发型漂移）。→ 印证 C77 跨镜锁特征，且比纯图多一种"参考视频"锁法。
  3. **定价真相（别被营销页骗）**：1080p 专业档 10s≈70 积分（Pro $37/月 3000 积分，考虑 40–60% 失败重跑，**月实际可用 15–20 条 10s 成片**）；免费层 66 积分/天（约 3–6 条）；**失败生成照扣全额、订阅积分月清空、有"99%卡死"扣费 bug、Trustpilot 1.5/5（账单/客服差）**。→ 第一步云快验可用免费层试水，但别把它当稳定生产管线。
  4. **能力边界（诚实）**：群体 >5–6 人崩脸、物理（球瞬移/流体）不稳、手特写仍抖、音频质量 3/5（口型"研发级非商用级"）、续拼 30–60s 后漂。最长 15s、原生 4K/60fps、单次最多 6 镜。
- 适用场景：下一步多角色 + 第一步带对白云快验；与 Seedance 分工——Seedance 长于 30s 环境/产品/连续，Kling 长于人物对白/近景人像。

### 1.5 Helios — 14B 开源视频模型，60s 实时、6GB offload（长叙事本地候选，记录）
- 来源：[creativeainews — Helios 14B Open-Source Video Model](https://www.creativeainews.com/blog/helios-14b-open-source-video-model-realtime/) · [github.com/PKU-YuanGroup/Helios](https://github.com/PKU-YuanGroup/Helios)（PKU + 字节 + Canva，Apache 2.0，2026-03-04）
- 核心要点：14B 自回归扩散，**单 H100 19.5 FPS、最长 ~60s（1452 帧@24fps）**；T2V/I2V/V2V；**Group Offloading 下 ~6GB VRAM 可跑**；社区 ComfyUI 节点已在出。→ 本地长叙事（补 LTX 20s 上限）新候选，但**6GB 跑 14B 是 offload 极限、画质/速度需实跑验证**，且发布已久（3 月），列为**待评估**而非优先。

### 1.6 ModelScope 中文权威教程：ComfyUI 角色一致性 AI 短剧工作流（印证"角色圣经六视图"）
- 来源：[modelscope.cn/learn/435042](https://www.modelscope.cn/learn/435042)（魔搭官方 learn，中文，可直读）
- 核心要点：角色资产库建议含 **正面 / 45° / 侧面 / 背面 / 表情 / 动作参考** 六视图；固定年龄/五官/发型/服装/身材比例/色彩风格；结合 Reference Image + LoRA + IPAdapter 增强稳定。→ 与 C98 角度包（3–5 视图）高度一致，且是**中文权威出处**，可作为我们写《桃子角色圣经 SOP》的引用模板。整体流程与我们「Qwen 出图 → ComfyUI → Wan/LTX 图生视频 → 超分 → 剪辑」同构。

### 1.7 LTX-2.5 提示词/纪律再确认（多源，非新工具，坐实基线）
- 来源：[ltx.studio 提示词指南](https://ltx.studio/blog/ai-video-prompt-guide) · [ltx.io I2V 工作流](https://ltx.io/model/model-blog/image-to-video-workflow) · [theneuron × LTX 团队直播](https://www.theneuron.ai/explainer-articles/ltx-2-5-video-prompting-for-beginners-full-guide-with-timestamps) · [creatide 完整指南](https://creatide.ai/blog/ltx-2-5-complete-guide-features-limits-workflows)

### 第一步：桃子单角色带情节视频（当前最高优先）

## 3. 及时调整建议

**增量强化，不推翻现有主线。**

1. **第一步 SOP 升级（零成本，最高优先）——把 1.1 锚帧纪律固化**：
   - 出图线 A 产「角色圣经 4–5 图（正面/侧/表情/各镜姿态）」，先两两比对"像不像同一人"，不像重出（呼应 1.6 六视图）；
   - LTX I2V 用本镜圣经图作首帧，**denoise 压到 0.25–0.5**（只做轻运动）；
   - 段末帧 inspect，漂移即 inpaint 修，存为下一段 handoff；
   - 加 IPAdapter FaceID（weight 0.8）作安全网；
   - 多 cuts 优先 LTX 原生多镜（C106/C107），长镜再用"首镜→末帧续生成"拼接（呼应 C94/C102）。
   - **替换/补充**：原"逐镜 I2V 再拼接"→ 优先"原生多镜单次生成 + 必要处低 denoise 接力"，从架构层降漂移。
2. **维持 LTX 主线**：1.7 再确认最快/最低伪影/原生多镜/可微调；HF 门控（C69）仅多一步账号操作，不换模型。
3. **多角色/长叙事新增本地开源候选 SkyReels-V3（C117）**：比纯云 Kling 更对口"本地多角色保身份+背景"，且开源无 IP 风险；第一步跑通后评估本地部署（low_vram 可上 A10）。Helios（C118）列为长叙事备用候选。

> 未发现比「Qwen-Image-Edit 锁角色 → LTX 出视频」更优且能在 A10 24GB 落地的"第一步"替代链，故**不调整第一步主线**；调整集中在"纪律细化（1.1）+ 多角色/长叙事预研补位（C117/C118）"。
