## 1. 新发现（教程 / 工具 / 工作流）

### 1.1 LTX-2.5 视频域角色 LoRA 训练精确配方（官方 + 实操，命中「第一步/下一步」）
- **官方 LTX Trainer 指南**（website.ltx.io/blog/training-your-first-lora-on-ltx）+ **CSDN《LTX-2.5 微调训练完全指南》**（blog.csdn.net/gitblog_00782/article/details/159526327）
- 核心要点：
  - LoRA 类型分两种：**Plain/Character LoRA**（锁角色长相+动作，rank 16–64，学习率 ~1e-4，数千步）与 **IC-LoRA**（锁控制/条件，如 pose/depth/canny/光照迁移、音频注入）。
  - **关键硬约束（新、可直接落地）**：`num_frames % 8 == 1`（即 1/9/17…121 帧）；宽高必须能被 **32 整除**。这两条贯穿数据预处理与推理全程。
  - 数据集：~50 条视频片段（5–30s，主体清晰、风格统一）+ 结构化英文提示词；训练前先留 3–4 条做干净验证。
  - **重要纪律**：IC-LoRA 训的是「控制」而非精细身份，牙齿/眼镜等细节要锁在「首帧图」上，别指望 IC-LoRA 还原。
  - 官方称 2.3 时代 LoRA 绝大多数可直接用于 2.5（少量例外需逐一验证）；推理可挂官方 `ltx-2.5-22b-distilled-lora-450-bf16` 提速。
- 适用场景：**训一个「桃子视频域 LoRA」** → 比单纯首帧/参考图更强的跨镜身份锁，直接服务第一步单角色带情节，且天然复用为下一步多角色的身份资产。

### 1.2 LTX-2.5 多参考 360° I2V 实测（单角色一致性，印证第一步）
- **mobdome《影片角色不连贯？三招搞定》**（mobdome.com/blog/ai-video-consistency-guide）
- 方法：用 Midjourney/SD 出角色全身正脸 → LTX-2.5 I2V 上传作首帧 → 进阶可传「正/侧/背」多张参考图学 360° 外观，转方向不崩脸。实测 30s 短片 5 段场景角色完全一致、和服花纹还原。
- 与基线 08-07/08-29「360° orbit 参考表」完全对齐，坐实「多参考 I2V」是第一步最稳路径。

### 1.3 LTX-2.5 速度与本地定位（厂商口径，参考）
- **tradepoint.io / truescho.com**：LTX-2.5 标称 10s 片在 2×GB200 上 6.8s、API 23.7s；称快于 Seedance 2.5（317s）、FLUX 3（259s）、Kling 3.0 Pro（398s）。native multishot + DFR 新解码器 + Gemma 4 12B + LTX-2 Community License（年营收 <1000 万免费）。属厂商宣传，作「本地批量过夜产片」方向参考，非独立基准。

### 1.4 MiniMax H3：RAVEN 流式 + 24GB 实证 + 加速栈（强化本地对比/质量轨道 C55/C57）
- **ComfyUI Wiki《H3 RAVEN LoRA》**（comfyui-wiki.com/en/news/2026-08-18-minimax-h3-raven-streaming-lora）+ **agihunt 2026-08-26**
- RAVEN（帝国理工）4-NFE LoRA（r=128）把 H3 变因果流式生成，官方 ComfyUI 节点 **ComfyUI-MiniMax-H3-RAVEN-Streaming**（08-20 发布）；实测 **1376×768 / 192 帧 / 24fps 在 24GiB 显存包内跑通** → **坐实 A10 24GB 本地可跑 H3**（修正 08-27「需 ≥64GB 内存」为「RAVEN 路径 24GB 即可，常规路径仍建议大内存」）。
- 加速生态：PlagueKind **SLA Node v1.3.5**（可配 dense steps）+ NVIDIA「H3 4-step 草稿 → LTX Sol-Attn 精修」22.2× 管线 + H3 **Studio 1939 LoRA**（1930s 手绘动画风格）。
- **⚠️ 实操坑（CSDN 评论）**：H3 官方 R2V 工作流（video_minimax_h3_r2v.json）默认只接 **2 张图参考**（非规格宣称的 9 张），多角色参考需改节点/分批。
- 许可证（kingy.ai 复核）：Community License 排除美/欧/英/韩，年营收 <2000 万美元需署名；**中国自托管 OK**。

### 1.6 Pixelle-Video：开源全自动短视频装配引擎（可作「成片装配」层，新候选 C62）
- **AIDC-AI/Pixelle-Video**（github.com/AIDC-AI/Pixelle-Video，Apache-2.0，11K+ Star；agentpedia.codes 深度解析；CSDN 介绍）
- 流水线：主题/固定脚本 → LLM 写分镜文案（通义/GPT/DeepSeek/Ollama）→ ComfyUI/RunningHub 生成图或视频 → TTS（Edge-TTS 免费 / Index-TTS 声音克隆）→ 加 BGM → HTML 模板合成成片。
- 模块化：生图模型可换 FLUX、TTS 可换、竖/横/方模板齐；Windows 一键包（解压双击 start.bat，localhost:8501）；Python ≥3.11 + uv。
- 定位：它是**编排/装配工**，不是生成模型。默认审美「及格水平」、用自有生图流程，**不能直接套我们的 Qwen-2512 角色圣经 + LTX-2.5**；但「分镜→ComfyUI→TTS→合成」编排骨架可借鉴，用于降低 Step3 漫剧 / Step1 长片的剪辑摩擦。
- 已知坑（issue）：ComfyUI 缺节点(#182)、本地/云端路由混淆(#188)、Edge-TTS 不稳、合成卡顿(#187)、API 路径遍历安全 PR(#175，勿公开暴露)。

### 1.7 AI 漫剧 7 步工业标准（印证 v4 漫剧骨架 C48，非新工具）
- **今日头条/搜狐/sohu 多篇**（小云雀 AI 短剧 Agent、扣子 Coze 工作流、北航清华团队报告 sgpjbg.com.cn）
- 行业收敛链路：**剧本/分集 → 角色三视图 + 场景母版（基准资产）→ 故事板分镜 → 逐镜生成 → 局部返工 → 配音精剪 → 人工审片**。
- 一致性框架（北航清华）：「四维一致」= 外貌 / 气质 / 风格体系 / 构图习惯；场景一致 = 环境+光影+色彩+细节；控制策略 = 顺序生成法（静→微动→动态）+ 回退修正法。
- 与我们 v4 漫剧骨架（Qwen 分镜 → IP-Adapter-FaceID+LoRA+ControlNet+Adetailer → LTX-2.5 多镜）**方向完全一致**，强化 C48 正确性，无需改基线。

## 3. 及时调整建议

🔴 **不替换 v4 基线**。三步微调建议：

1. **🆕 加「桃子视频域 LoRA」训练（C61）**：在现有「Qwen-2512 角色圣经（出图）+ LTX-2.5 首帧/I2V（视频）」之上，增加视频侧身份锁——用 LTX-2.5 Trainer 训 rank16-64、~50 段素材、严守 `帧%8==1` 与 `宽高%32` 约束。理由：单参考/首帧在强运镜下仍可能微漂，视频域 LoRA 是 2026 业界「硬身份锚」标准做法（aivid/domer 多源印证），且一次性训练、可复用于下一步多角色。替换的是「视频阶段仅靠首帧」这一步，不推翻出图线 A。

2. **🆕 引入 Pixelle-Video 式装配层（C62）**：桃子带情节视频一旦超过 30s / 多镜，剪辑拼接是摩擦点。借鉴其「LLM 分镜 → ComfyUI 生成 → TTS → 模板合成」编排，把我们的 Qwen-2512+LTX-2.5 塞进生图/生视频槽位，保留角色圣经与本地可控。不替换任何生成模型，只补「成片」短板，并直接服务最终漫剧。

3. **维持 H3 本地轨道但优先 RAVEN 路径（C55/C57 实证）**：RAVEN 已验证 24GiB 包内 1376×768/192 帧，比常规 ~34GB 路径更贴合 A10；若上 H3 本地对比，先用 RAVEN 流式节点。

4. **纪律红线保持不变**：所谓「Seedance 3.0」仍为聚合站编造（08-28 已禁用）；`ltx25.org` 仿冒站勿信（见 1.8）；Wan 3.0 / H3 本地主线仍排除（闭源 / 常规路径吃内存），仅作云/大显存并列。
