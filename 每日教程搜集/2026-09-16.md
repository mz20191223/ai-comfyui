## 1. 新发现：教程 / 工具 / 工作流

### 【C133】LTX-2.5 "Ingredients" 复合参考图工作流（ronald-fong 引 LTX 文档）
- 来源：https://ronald-fong.com/top-ai-video-generation-tips-in-2026
- 核心：把角色 / 道具 / 环境**合成一张 reference sheet（参考表）**作为输入（作为静态视频喂给模型），而非分别上传多张参考图。模型不是当 UV 映射/精灵表，而是把图当作"有组织的视觉上下文"——清晰分区即可（左上=脸、右上=身体、下=环境）。
- 与既有"角色圣经（多张角度图）"互补：可把桃子的角色立绘 + 关键道具 + 场景一次性打包，减少多参考图顺序错乱（呼应 C121 顺序纪律）。
- 适用：LTX 主线出图阶段"一图打包资产"，待验证 LTX-2.5 是否真按此理解（官方文档需复核）。

### 【C134】小云雀 AI 工作台（即梦 / Seedance 2.5 剧作模式落地入口）
- 来源：https://www.sohu.com/a/1075753025_122918358
- 核心：字节系承载 Seedance 完整创作链路的专业工作台，闭环 = 剧本 → 资产组织（角色卡/场景卡/风格参考）→ 故事板拆镜（秒级时间段描述）→ 生成 → 局部返工。
- 容量：Seedance 2.5 最多 **30 图 + 10 视频 + 10 音频 = 50 份多模态素材**联合；一份素材只承担一个职责，冲突时先减素材而非加量。
- 适用：云快验"Seedance 剧作模式（C123）"的**首选落地入口**——比零散 API 更省返工，直接服务第一步 30s 桃子带情节叙事。
- 注：此即此前 C123「剧作模式」的具体产品载体，坐实入口。

### LTX-2.5 部署纪律坐实（RunPod 官方博客）
- 来源：https://www.runpod.io/blog/ltx-2-5-the-open-weights-world-model-built-for-speed-and-how-to-run-it-on-runpod
- **硬纪律（零成本、立即固化进我们 LTX 主线部署 SOP）**：
  - 权重为 **22B**，VRAM floor **16GB**；int8-convrot 的 `*-comfy-int8-convrot` 文件**仅 ComfyUI 可用**，PyTorch/ltx-pipelines 路径不认（会报错）。
  - 随卡 Gemma 4 文本编码器**是 LTX 专用**，Google 官方 Gemma 4 不能替（pipeline 会校验编码器版本）。
  - HF 仓库 `Lightricks/LTX-2.5` **门控需申请**（接受许可 + 等审批 + Read token 带 gated 权限），401/403 即缺这两步。
  - 原生多镜：在单次生成内保持**角色/场景/灯光/声音跨切一致**；4K HDR 输出。
- 印证 C69（门控）/ C12（基线）；无推翻，纯部署细节补强。

### 多镜头一致性三级模型 + 角色锚定中立帧 + 连续性日志
- 来源：https://therightgpt.com/how-to-keep-characters-consistent-across-multiple-ai-video-shots ；https://consistentcharacter.ai/blog/best-ai-tools-for-animated-storytelling ；https://domer.io/blog/multi-image-fusion-ai-filmmaking-guide
- **一致性三级（2026 主流方法论）**：
  - Level 1 纯提示词重复描述 → 仅 2–3 简单镜，长序列必漂。
  - Level 2 参考图/元素锁定（@Element）→ 单平台有效，跨引擎不稳。
  - Level 3 **结构化序列 + Hero Lock（推荐）**：角色/环境/灯光/色温一次定义、所有镜继承，3+ 镜可扩展、跨模型可用。
- **角色锚定 = 一张全身体中立帧（front/three-quarter）**，所有工具服从此参考；印证我们"角色圣经"做法，强调"中立帧而非花哨姿势"。
- **跨场景测试**：用 5 个无关场景（森林/厨房/地铁/天台/海滩）测同一人，漂移即返工——在我们"角色圣经两两比对"基础上加一道自动化校验。
- **连续性日志**：每镜记服装/道具/时段/角色朝向，新镜生成时查表——低门槛零成本纪律。
- 印证并细化 C98 / C122，可直用并入 SOP v2。

### 首尾帧规则对比（服务"末帧 handoff 串镜"策略）
