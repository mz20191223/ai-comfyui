### 1.1 🔴 LTX-2.5 社区 GGUF 量化可用，A10 24GB 显存拦路虎解除（今日头条，去风险）
- **来源（实测/权威）**：
  - RTX 5080/5060 Ti 16GB 实测（smeltcore，逐字节清点）：https://smeltcore.com/recipes/ltx-2-5-on-rtx-5080-22b-audio-video-in-16-gb-and-what-the-wider-bus-cannot-buy ｜ https://smeltcore.com/recipes/ltx-2-5-on-rtx-5060-ti-22b-audio-video-in-16-gb-via-a-community-q3-k-m-gguf
  - 全量化安装清单（stablediffusiontutorials，含 GGUF 出处 RebelAI/Abiray/VantageAI）：https://www.stablediffusiontutorials.com/2026/08/ltx-25-video-generationint8bf16nvfp4gguf.html
  - 低显存 WanGP 支持 LTX-2.5（6GB+，Pinokio 一键）：agihunt 实测集 https://agihunt.info/story/19ff7e5bbd62ccd9456222b7716
- **核心要点（逐字节显存数学，关键）**：
  - 官方默认模板指向 `ltx-2.5-22b-distilled-transformer-comfy-int8-convrot`（21.5GiB）→ 16GB 卡跑不了，但**可替换为社区 GGUF**，图其余部分不变。
  - 常见 GGUF 量化（transformer 文件体积）：Q2_K realrebelai 8.3GiB / **Q3_K_M realrebelai 10.7GiB** / Q3_K_M Abiray·VantageAI 12.9GiB / Q4_K_S realrebelai 13.9GiB / **Q4_K_M realrebelai 15.1GiB** / W4A8-ConvRot(Winnougan) 12.5GiB / nvfp4(DmitryDB 重建) 13.6GiB / 官方 nvfp4 18.7GiB / 官方 INT8-convrot 21.5GiB。
  - **常驻显存只算 transformer + VAE + 超分**（VAE 视频 1.35GiB + 音频 0.34GiB + 空间超分 0.93GiB ≈ 2.62GiB 固定）；**Gemma4-12B 文本编码器（14.3GiB）是顺序阶段，提示词编码后即卸载，不与采样同时占显存**。
  - 实测：RTX 5080(16GB) 跑 Q3_K_M 常驻权重 13.35GiB，峰值 15.54GiB（留 2.6GiB 余量）→ **跑通**；RTX 3060 12GB 跑默认 INT8（offload 流式）15s 视频约 5 分钟。
  - **结论映射到我们**：A10 24GB 跑 **Q4_K_M（~15.1GiB + 2.62GiB ≈ 17.7GiB 常驻）非常宽裕**；Q3_K_M 更省、更快、质量略降。T4 15.9GB 跑 Q3_K_M 临界（16GB 卡实测峰值 15.5GiB），不建议压 T4。
  - 向后兼容：2.3 的 LoRA **直接换权重即可用**，无需改工作流。
- **适用场景**：视频主线升级 LTX-2.5 的**唯一硬件拦路虎（显存）今日确认解除**——A10 24GB 可落。

### 1.2 🟢 LTX-2.5 多镜提示词纪律 + 6 项抗压测试（直接服务桃子第一步一致性）
- **来源**：
  - Frontier Models 实战教程（多镜/首末帧/2K + 6 项压力测试修身份漂移/转场故障/物理 bug）：https://frontiermodels.cc/video/master-ltx-2-5-in-comfyui-multi-shot-first-last-frame-2k-workflows
  - Runpod 实测跑通指南（多镜散文写法 + Prompt Enhancer + 双 CFG 引导）：https://www.runpod.io/blog/ltx-2-5-the-open-weights-world-model-built-for-speed-and-how-to-run-it-on-runpod
  - ai-bot.cn 中文能力/参数说明（帧率 24/25/48/50fps，宽高 32 倍数，帧数 1+8 倍数）：https://ai-bot.cn/ltx-2-5
- **核心要点**：
  - **多镜写法**：把整段序列按时间顺序写成一段连贯散文，用散文点名切点（"A hard cut transitions to a close-up..."）→ 模型一次出连续远/中/近镜并跨镜锁角色/环境/光线/嗓音。这正是「桃子带情节」的天然形态。
  - **Prompt Enhancer**：轻量辅助模型，把短提示扩成电影级指令（降低提示词门槛，略增时长）。
  - **双 CFG Guider**：音频 CFG 与视频 CFG 分开控（ComfyUI 节点原生）。
  - **6 项压力测试出的坑与修法**：身份漂移、转场故障、物理逻辑 bug；**prompt hack：年轻亚洲脸用 "girl" 而非 "woman"**；避免 "soft umbrella" 故障（伞面穿模）、门穿模、复杂动作链需拆步验证。
  - 速度标杆：10s 1080p 约 2 分 34 秒（比 H3 快约 6×）；3060 10s 视频约 3 分钟；5090 10s 720p 约 2 分钟。
- **适用场景**：桃子第一步「单角色带情节」编排骨架 + 一致性避雷手册。

### 1.3 🟡 LTX-2.5 vs MiniMax H3 真实横评：速度王但画质/物理有短板（预期管理）
- **来源**：agihunt 社区实测聚合（2026-08-11~14，多创作者）：https://agihunt.info/story/19ff7e5bbd62ccd9456222b7716
- **核心要点**：
  - LTX-2.5 = **速度碾压、低显存友好、多镜原生**；短板：镜头运动与微细节、人体结构变形、物理规律翻车、面部细节仍有瑕疵（社区对画质有分歧，@PuppetHere 认为与 2.3 无明显差异）。
  - H3 = **真实感/图生视频(I2V)/名人IP识别更优**，但本地显存门槛高、慢。
  - 结论：**无绝对赢家**；LTX-2.5 适合做「视频工作流增强/多镜快出」，H3 适合质量敏感镜头。
- **适用场景**：桃子项目里「LTX-2.5 出多镜粗剪 + H3/Seedance 补质量敏感镜」的分工依据。

### 1.4 🟢 Seedance 2.5 角色一致性深度方法论（4 类漂移框架，第一步验证可直接套）
- **来源（官方/实操）**：
  - elser.ai《如何在 Seedance 2.5 中保持角色一致性》：https://www.elser.ai/zh/news/keep-characters-consistent-seedance-2-5
  - seedance.io 官方 R2V 工作流指南（3 个 reference-pack 范例 + 内联引用语法）：https://www.seeddance.io/blog/seedance-2-5-reference-to-video
  - ComfyUI 官方 Seedance 2.5 R2V/T2V workflow 下载：https://blog.comfy.org/p/seedance-25-is-now-available-via
- **核心要点**：
  - **4 类角色漂移诊断**：身份漂移（变脸）/服装偏移（左右扣饰）/性能漂移（举止不符）/空间漂移（瞬移、视线错）。先诊断类型再修。
  - **10 步纪律**：权威人物卡 → 身份锚点 → 左右解析 → 围绕可见性布镜 → 参考层级 → 提示身份块固定 → 表演/外观分离 → 服装道具当状态控 → 固定检查点审核 → 本地修再全局查。
  - **R2V 内联引用**：`@image1`/`@video1`/`@audio1` 在 prompt 中点名每个参考驱动哪部分（身份/运动/相机/声音）；冲突时按「识别属性→保留最清晰源、删其余→一句话定优先级→重生成」顺序修。
  - 参考上限：30 图 + 10 视频 + 10 音频；30s 单镜直出；时间线控镜；多语口型。
- **适用场景**：桃子第一步「单角色带情节」并行快验的一致性 SOP（比裸跑 Seedance 稳得多）。
