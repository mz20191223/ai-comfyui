## 1. 新发现：教程 / 工具 / 工作流

### 1.1 🆕【最高优先·直击「第一步 带情节/动作连贯」】LTX Director 2.0 —— 时间轴多段动作调度 + 内置音频口型
- 来源：实战 https://aistudynow.com/how-to-use-ltx-director-2-0-in-comfyui-perfect-multi-scene-video ；自定义节点 `WhatDreamsCost-ComfyUI`（ComfyUI Manager 搜该名安装）。
- **核心要点**：这是一个**可视化时间轴编辑器**自定义节点套件，把「多段提示词 + 音频 + 镜头运动」按**精确时间轴**排进单次渲染 —— 正是我们「桃子单角色带情节视频」长期缺的那块「动作连贯 / 时序可控」引擎。
  - **多段动作（Prompt Relay）**：在 24fps、Seconds 模式下，右键时间轴「Add Text Segment」分块。例：1–3s「桃子慢慢抬手、把烟凑近脸」，3–6s「桃子放下手、烟袅袅飘起」。AI 按时间顺序逐段执行，动作平滑连贯，不是单全局 prompt 硬坨。
  - **音频引擎 / 口型同步**：内置音频轨，加载对白/歌曲，把时间轴切成 5s 块并对齐视觉提示；因音视频同模型处理，输出口型自然对齐。（与我们 07-29 的 LipDub / ReferenceAudio 形成互补，Director 是「生成期」就把音频当作控制层。）
  - **起始图铁律**：起始图必须在时间轴停留 **≥1 秒**，之后 segment 编辑器才激活写动作描述。
  - **磁力吸附（Magnet）**：开启后各段自动吸附对齐，防跳变。
  - **模型装配**：Dev **FP8** LTX 2.3 + Distilled LoRA 1.1 + Dual CLIP（Gemma 3 12B + LTX 文本编码器）+ LTX **video & audio VAE** + 辅助 LoRA（transition LoRA 平滑转场、VBR LoRA 修物理）。
- **适用**：**第一步「桃子带情节」的第一引擎候选**——给桃子一条 10–20s 单镜，按时间轴分段写动作+对白，一次出连贯带口型成片。比单纯 I2V 强在「时序可控、动作不漂移」。

### 1.2 🆕 LTX 2.3 Movie Builder（Mickmumpitz）—— 多场景成片流水线（服务下一步/最终漫剧）
- 来源：runcomfy 工作流 https://www.runcomfy.com/comfyui-workflows/ltx-2-3-movie-builder-workflow-in-comfyui-multi-scene-ai-filmmaking
- **核心要点**：把「脚本行 / 参考图 → 多镜成片」工业化的 ComfyUI 流水线：
  - **提示词三段式** `[VISUAL] 场景描述 / [SPEECH] 原话 / [SOUNDS] 音色与环境音` —— 让 LTX 文本/音频编码器协同。
  - **关键节点**：`LTXVImgToVideoInplace`（高清静帧→时序一致视频潜变量，**保身份保构图**）、`LTXVReferenceAudio`（注入语音/音乐节拍做口型+手势对齐）、`LTXVLatentUpsampler`（空间超分）、`ColorMatch`（跨镜色彩统一）、`MickmumpitzShotOrder`/`ShotDuplicator` + `Video Output - Shot Assembler (#5598)`（裁切+拼接成单一时间线）。
  - **流程**：FLUX.2 出起始静帧/道具/场景 → LTX 2.3 I2V 动画化（配 LTX ID LoRA 锁身份）→ 各镜输出 → Shot Assembler 拼成电影。
  - **低显存**：GGUF 版 LTX 2.3 + 别叠额外 LoRA 直到最终 pass；复制 SHOT 01 改 prompt/出入点即可加长。
- **适用**：**下一步多角色 / 最终漫剧的「多镜组装层」**；与 1.1 Director（单镜时序）互补——Director 管「一镜内动作」，Movie Builder 管「多镜拼接成片」。

### 1.3 🆕 LTX IC-LoRA Motion Track / Union Control —— 精准动作与姿态控制（服务「动作连贯」）
- 来源：官方 IC-LoRA Adapters https://docs.ltx.video/open-source-model/integration-tools/ic-lo-ra-adapters ；Motion Track 工作流 https://www.runcomfy.com/comfyui-workflows/ltx-2-3-ic-lora-in-comfyui-v2v-motion-track-video-workflow ；实战 https://frontiermodels.cc/video/iclorahow-to-perfectly-control-ai-video-motion-ltx-2-3
- **要点**：
  - **Motion Track Control**：用稀疏样条轨迹（`LTX Draw Tracks` 画板 + `LTX Sparse Track Editor` 微调关键点/时序）**精确指挥主体运动路径**——比纯文字描述更可控；支持单/多物体独立路径。例：zoom-in / 环绕 / 物体按轨迹移动。
  - **Union Control**：depth + canny + pose **三合一单 checkpoint**（默认参考强度 0.5），省去换三个 IC-LoRA、省显存。
  - **实战铁律**：高动态源视频 **LoRA weight 设 0.5（非默认 1.0）**，否则角色崩塌；参考视频缩到最短边 544px，控制图 512px，参考图最长边 1536px、压缩因子 18。
  - **低显存**：用 `unsloth/LTX-2.3-GGUF` 量化版（见 1.6）。
  - 另有官方 `Text Generate LTX To Prompt` 节点（用 CLIP 当 LLM 把结构化模板扩写成电影级提示词）。
- **适用**：桃子单镜内「指定动作路径 / 指定镜头运动」的精细控制；与 Director 2.0 形成「轨迹级 + 时间轴级」双保险。

### 1.4 🆕 Qwen-Image-2512 真实可用（降塑料感 + 一致性提升）+ 2512-Edit_Multi
- 来源：blog.csdn 换装换背景实测 https://blog.csdn.net/weixin_35903223/article/details/157669922 ；图像改造 https://blog.csdn.net/weixin_42163404/article/details/157498540 ；网心算力云解读 https://onething.net/media/462.html
- **要点**：
  - **Qwen-Image-2512（文生图底座）**：针对性改善人物「塑料感」（皮肤纹理、发丝、表情神态），能理解「微微前倾」等精细语义；文字排版/多格漫画更强。**相对 2509 一致性大幅提升**。
  - **Qwen-Image-Edit-2511**（我们 HAI 已部署 GGUF）：相对 2509 进一步减轻图像漂移、提升单/多人一致性、内置 LoRA、精准文字编辑+多图融合。
  - **2512-Edit_Multi 工作流**：用 `QwenImageEditPlus` + **跨图像注意力（Cross-Image Attention）** 一次融合多参考（文字风格迁移准确率 >85%），即 2512 时代的「多参考一次出」（与 07-29 的 2511 `TextEncodeQwenImageEditPlus` 同源思路，节点名略异）。
  - **参数**：2512 已取消 denoise 手动干预（内置 AuraFlow 调度）；正式出图 steps 22 / CFG 5 / 开 Consistency 为黄金组合。
- **适用**：**出图线 B（任意新角色/场景）升级候选**；出图线 A（桃子参考集）维持 2511 GGUF 不动（已部署、稳），**若后续出现 `Qwen-Image-Edit-2512` GGUF 再评估升级出图线 A**（一致性/降塑料感进一步收益）。

### 1.5 🆕 Qwen3-TTS 本地角色嗓音锁定（闭环节点，多 fork + 多角色广播剧）—— 闭合「桃子带情节」对白
- 来源：aakash-chaddha/ComfyUI-Qwen3-TTS（https://github.com/aakash-chaddha/ComfyUI-Qwen3-TTS）、TravellerEntity/ComfyUI-Qwen3-TTS（多角色广播剧引擎）、1038lab/ComfyUI-QwenTTS
- **要点**：阿里 Qwen3-TTS 的 ComfyUI 封装，可**在本地（我们 A10/ComfyUI 内）**给桃子造一把「可复用、跨集一致」的嗓音：
  - **Custom Voice**：9 个预设（Vivian/Ryan…）；**Voice Design**：自然语言描述造声（如「撒娇萝莉音」）；**Voice Cloning**：3s+ 参考音频复刻；**Fine-Tuning**：用自己数据集训专属声。
  - **跨语种**：中/英/日/韩/德/法等 10 种。
  - **⭐ TravellerEntity fork 多角色广播剧引擎**：`RoleBank` 角色库 + `AdvancedDialogue` 多角色配音 + `[情感标签]`/`[pause:1.2]` 自动解析 + `ScriptProcessor` 脚本驱动 —— **直接服务「漫剧多角色对白」**，单节点生成多角色对话并自动拼接。
  - **模型**：1.7B / 0.6B（轻量，A10 可跑）；存 `ComfyUI/models/Qwen3-TTS/`。
  - **坑**：上游 `qwen-tts` 要求 `transformers==4.57.3`（可能降其他节点版本，建议独立环境）；Windows 无 FlashAttn → 用 `sdpa`；长参考音频(>30s)偶发死循环 → `max_new_tokens` 降到 1024、参考音频 5–15s。
- **适用**：**本地闭环给桃子配「 recurring voice」** → 音频喂给 LTX `LTXVReferenceAudio` / Director 2.0 音频轨 / LipDub Beta，实现「带情节+口型对齐+跨集嗓音一致」。比第三方 TTS（Inworld/ElevenLabs，见 1.8）更可控、IP 不外泄。**这是今天最务实、最能闭合「第一步」的本地增量。**

### 1.6 🆕 GGUF 量化 vs 全精度权重的现实张力（采用 Director 前必须知道）
- 来源：wavespeed.ai GGUF 分析 https://wavespeed.ai/blog/posts/ltx-2-3-gguf/ ；smeltcore RTX 4090 24GB 实测 https://smeltcore.com/recipes/ltx-video-2-3-rtx-4090 ；unsloth/LTX-2.3-GGUF
- **要点（关键修正/风险）**：
  - 社区 GGUF（QuantStack / Unsloth）是**社区量化**，非 Lightricks 官方；许可证同为 `ltx-2-community-license`（量化不剥离许可）。
  - **⚠️ 重大：LTX Director / camera-control 类扩展依赖「原始权重格式」，对 GGUF 构建「要么不工作、要么工作 imperfect」**（wavespeed 原文）。即：**我们想用 1.1 Director 2.0，可能必须用全精度/FP8 原权重，而非 GGUF。**
  - **A10 24GB 可行性拆解（smeltcore 实测）**：全精度 Gemma 3 12B 编码器需 ~24–27GB（塞不下 24GB）→ 必须用量化编码器 `unsloth/gemma-3-12b-it-qat-GGUF`（QAT-Q4 ~7.4GB）+ 蒸馏 GGUF transformer（Q4_K_M ~15–18GB）。两条策略：A) 量化编码器驻留 GPU（快，24GB 紧但可行，`--reserve-vram 4`）；B) `--novram` 从 RAM 流式（必装，慢但稳，5080 实测仅 3GB VRAM）。
  - **蒸馏设置**：steps 8 / CFG 1.0 / 宽高被 32 整除 / 帧数 `8n+1`（65/97/121）；dev 则需 ≥20 steps。
  - **我们的处境**：07-29 记「A10 跑 LTX 2.3 FP8 主权重 ~22GB」——这正是**原权重格式**，恰能喂 Director 2.0；代价是 22GB + Gemma 量化编码器 + 工作显存≈临界 → 必须配 `draft-then-upscale`（先 ~280p）+ `--reserve-vram`。
- **适用**：定调「A10 上 Director 2.0 走 FP8 原权重 + 量化 Gemma 编码器 + draft-then-upscale」，不走 GGUF（否则 Director 失效）。

### 1.7 🆕 Wan 2.7 最新基准 + 许可证差异（强化评估轨道）
- 来源：wanvideogenerator.com 五方横评 https://wanvideogenerator.com/blog/wan-2-7-vs-kling-3-vs-ltx-2-3-vs-skyreel-v4 ；studiolist.co 一致性专题 https://studiolist.co/guides/wan-2-7-multi-shot-character-consistency ；deepresearch.ninja 能力分析；pinggy.io 模型总览
- **要点**：
  - **Elo（Artificial Analysis Video Arena，2026-05）**：Wan 2.7 **1762**（开源第一梯队，领先 LTX-2.3 Pro 的 1484 约 278 分 → 盲测人类偏好约 83% 胜率）；LTX 2.3 = 开发者/规模化最优选（$0.04/s 最便宜）。
  - **Wan 2.7「解决了一致性」**：MoE 27B（14B 激活）、9-grid 多图输入 + **150+ 参考帧**跨镜锁身份、首/末帧控制、原生音频、NVFP4 量化可 24GB（A10）。Apache 2.0（**比 LTX 社区许可更宽松**——LTX 社区许可禁止与 Lightricks 竞争产品、> $10M 营收需付费商用）。
  - **结论**：对「下一步多角色 / 最终漫剧」多镜一致性，Wan 2.7 是当前开源最强；但 LTX 对我们（< $10M、非竞品）许可无碍，且本地成本最低、Director/Movie Builder 生态现成。
- **适用**：维持 07-29 的 Wan 2.7 评估轨道；**第一步跑通后做 2–3 镜对比**，若跨镜一致性显著胜出再迁视频主线（出图线 A 不变）。许可证维度 Wan 更友好，record 备查。

  - **Pika Director's Suite（2026-07）**：一句话→完整影片（概念/脚本/分镜/角色一致/场景生成/时间线/音效），Claude 驱动；4K-VFX 局部改（保脸/保音频/保运镜）。**第三方。**

### 1.9 🆕 LTX 2.3 video-to-video（pose/depth/edge）实战坑（视频阶段必读）
- 来源：mindstudio.ai https://www.mindstudio.ai/blog/how-to-use-ltx-23-video-to-video-controls-pose-depth-edge
- **要点**：
  - **2 秒悬崖**：v2v 对 < ~2s 的片段不是降级而是**直接失败**；解法：把片段半速（50%）拉长到 > 2s，处理后裁掉 padding（代价：时序分辨率降、可能口型错位）。
  - **正脸反转 workaround**：pose 模式靠强参考锚身份；若片段开头无脸（背影/远景），pose 模式会漂——把片段**倒放**（脸先出现）处理后再倒回。
  - **模式选型**：相机运动/跟拍→depth；人物/清晰身体→pose（但侧脸/快动作会漂身份，须强参考）；结构/实验→edge（**edge 最易肢体变形，属预期行为非 bug**）。
  - **多角色分镜**不同镜用不同模式，分别处理再 cut。
- **适用**：我们桃子视频阶段若走 v2v（参考视频驱动），务必避开 2 秒悬崖、正脸反转保身份。
