## 1. 新发现：教程 / 工具 / 工作流

### 1.1 可灵 Kling 3.0 全量开放（重大，直接影响三阶段目标）
- **官方发布说明**（https://klingai.com/release-note/release-notes/whbvu8hsip；官网 https://klingai.com/?page=nextgen）：可灵视频 2.6 → **视频 3.0**，O1 → **视频 3.0 Omni**，已全量开放。
- **视频 3.0 核心能力**（对比 2.6 新增）：
  - **智能分镜**：AI 导演入驻，一次生成即为一支成熟影像叙事（自动调度景别与机位、对话正反打、台词跨分镜、画外音）——**直接命中「带情节」甚至「漫剧多镜头」**。
  - **原生音画同步**：文本与视觉角色精准映射，多人同框「想让谁说就谁说」，多语种+方言+多语混说。
  - **首帧 + 主体参考**：可上传/录制视频主体并加音色控制（锁角色+锁嗓音）。
  - **三人及以上指代 / 多角色**：解决多人场景指代混乱——**直接服务「下一步：多角色」**。
  - **15s 生成 + 灵活自定义秒数**。
- **视频 3.0 Omni 核心能力**：多镜头画面生成、最长 15s、主体参考、音色控制、智能分镜。
- **横评坐标**（anyvids.ai / twoshot.app 对比表，厂商自报、含第三方整理）：Kling 3.0 = 2K/4K、15s、60fps、单视频最多 **6 个镜头切换**、原生 Omni 音画、最多 **3 人追踪**、Character Feature Library 跨镜锁特征。对比 Seedance 2.0（1080p/15s/多镜）、Sora 2（**已 Discontinued 退役**，印证 C54 方向）、Veo 3.1。
- **对桃子第一步的意义**：智能分镜 + 15s + 原生音画 + 主体参考，一条提示词即可出「带情节、有镜头语言、自带配音」的单角色短片，比 Seedance 2.5 的「30s 一镜无分镜」更贴合「带情节」定义，且省去单独配音环节。

### 1.2 Toonflow 开源 AI 短剧工厂（漫剧装配层最强开源候选，坐实）
- **GitHub**：https://github.com/HBAI-Ltd/Toonflow-app （前端 https://github.com/HBAI-Ltd/Toonflow-web；官网 http://www.toonflow.net/；Gitee 镜像同路径）。截至目前 ~11.8K stars / 2.1K forks，最新稳定版 v1.1.8（2026-06），AGPL-3.0（部分资料记 MIT，以仓库 LICENSE 为准）。
- **定位**：小说/一句话 → 剧本 → 分镜 → 角色卡 → 出图 → 视频 → 配音字幕剪辑 → 成片，**全链路本地部署、永久免费开源**，数据不出本机。
- **核心机制**：
  - **三/两层 Agent 协作**（决策层/执行层 scriptAgent+productionAgent/监督层），模拟真实影视团队，质量超单一 LLM 直出。
  - **角色一致性保持**：角色卡 + 角色锚定系统，跨场景跨镜头不变脸——**直击 AI 漫剧最大痛点**。
  - **章节事件图谱**：长文本导入先做事件抽取存 SQLite，改编时精准召回上下文，避免长文压成单 prompt 丢伏笔。
  - 批量生产：单章节一次生成 10+ 关联短场景；自带调度器。
- **部署**：Windows 桌面一键装（默认 admin/admin123）、Docker（:60000）、手动 yarn。需自配外部 API（LLM 推荐 GPT-4o/Claude 4 Sonnet、图像 Nano Banana Pro、视频 Sora/豆包视频），可走 32AI 中转降本。
- **对 Step3 漫剧的意义**：相比此前 C62（Pixelle-Video）、C75（Stixx / Dify+ComfyUI）的「方向印证」，Toonflow 是**成熟度最高、star 最多、真正可一键本地跑通**的开源短剧工厂，应作为漫剧装配层**开源首选候选**。

### 1.3 LTX-2.5 All-In-One 工作流（低显存利好主线）
- **来源**：https://lilys.ai/notes/en/comfyui-20260826/ltx-2-5-all-in-one-workflow-comfyui ；RunComfy 官方 I2V+音画工作流 https://runcomfy.com/comfyui-workflows/ltx-2-5-comfyui-image-to-video-synced-audio ；官方工作流指南 https://staging.ltx.io/blog/comfyui-workflow-guide 。
- **要点**：单一工作流集成 **8 种生成模式**（文生视频 / 图生视频 / 首尾帧 / 图+音频口型 / 首尾帧+口型 / 首中尾帧+口型 / 音频生视频 / 视频转视频），**最低 8GB VRAM 可跑**（GGUF distilled + LoRA），角色一致性与电影质感显著改善。
- **官方参数纪律确认**：蒸馏模型 4–8 步 + 手动 sigma 调度；完整模型 20–50 步（40 步性价比高）；CFG 2.0–5.0（默认 3.0–3.5）；**Multimodal Guider 把 Prompt Adherence / Cross-modal Sync(STG) / modality scale 拆开独立调**——抖动就加 cross-modal sync，不跟提示词就加 prompt adherence，**绝不同时拉满**。
- **对 A10 24GB 主线的意义**：8GB 可跑说明 A10 跑蒸馏版余量充足；8 合 1 工作流把以往分散的「口型/首尾帧/音频」节点打包，降低搭建门槛，**强化本地 LTX 主线作为第一步+多角色的可控底座**。

### 1.4 Wan 2.2-S2V 音频驱动长视频（桃子带情节的另一条本地路径）
- **来源**：https://aiimagetovideo.pro/blog/long-ai-video-generator-comfyui/ 与 https://aiimagetovideo.pro/blog?p=1808 。
- **要点**：Wan2.2-S2V 由「角色图 + 音轨」驱动，生成对话/唱歌/表演视频，官方称支持**分钟级**生成，最适合「单角色按音频表演」的长视频。配合 LTX 的「生成首镜 → 取末帧 → 续生成 → 拼接」长视频延展法（每镜只加一个动作、保持人设/服装/光线/机位一致），可拼出连贯叙事。
- **对桃子第一步的意义**：若桃子用「先写配音/口播 → 图+音频驱动」的方式，S2V 比纯 I2V 更省事，且本地 Wan 2.2 开源可跑（A10 量化可行）。

### 1.5 中文「AI 漫剧 8 步流水线」多源对齐（强化第一步 SOP）
- **来源**：火星时代 https://www.hxsd.com/content/59471 ；18183 https://www.18183.com/gonglue/202608/l5e412g5.html ；2ds.cn https://2ds.cn/?p=19925/ （均为公开网页，非公众号原文 → 公众号/B站/小红书长文**需用户手动发链接**）。
- **共识流程**：① 剧本（3 秒黄金冲突钩子+每 30s 起伏+结尾留悬念）→ ② 角色三视图+角色卡（全程垫图锁脸）→ ③ 分镜静帧（统一画风/光影，只改动作）→ ④ 图生视频（**只写小幅动作**：眨眼/转头/抬手/微推，禁大幅跑跳打斗）→ ⑤ 多角色配音（每角色固定音色+情绪）→ ⑥ 剪映 7 步合成（字幕/转场/BGM/调色）→ ⑦ 审核（变脸/抖动/音画错位）→ ⑧ 导出 9:16 1080P/4K。
- **工具共识**：剧本用豆包/DeepSeek/Kimi；出图即梦（带角色锁定+三视图+小说推文模板）/ 通义万相 / 可灵绘图；图生视频即梦（一致性最好）/ 可灵 3.0（动作流畅天花板）/ Pika / Runway；配音剪映 AI；剪辑剪映。
- **与 C73 印证**：再次确认「即梦分身→三视图→图生视频→剪映」是中文最低摩擦路径；同时把「**动态提示词只写小幅动作**」坐实为防崩铁律——这对桃子第一步的镜头设计直接可用。

### 1.6 其他可用线索
- **comfyui-mcp**（artokun，https://deepwiki.com/artokun/comfyui-mcp/6.3-video-generation-(wan-and-ltxv2)）：把 WAN 2.2（Hi-Lo 双 UNET 双通道采样 + FLF 锚帧策略）与 LTX-V2 封装为 MCP 命令，可脚本化批量生成，适合做自动化流水线试验台。
- **LTX-2.3 两阶段工作流中文指南**（https://wan2.video/zh-tw/ltx-2.3-comfyui）：Stage1 低分辨率 base（8 步 CFG1 锁叙事）→ Stage2 spatial upscaler 精炼（4–6 步）；8–12GB 用 GGUF/FP8 跑 720p 直式，16–24GB 跑两阶段 1080p 直式（30–60s 出片）。印证 v4「蒸馏两阶段」纪律。
- **音乐视频 LTX-2.3 工作流**（earngenix，https://www.earngenix.com/workflows/ai-music-video-comfyui）：歌曲(ACE-Step/Suno)→ Krea2 角色一致性 → LTX-2.3 图+音频口型 → 剪辑，RTX4090 单镜最长 40s。**印证「音频驱动+口型」是 LTX 家族成熟范式**，桃子后续做「唱歌/口播」可照搬。
- **ComfyUI 视频生成通识**（comfyui.dev blog、Yotta Labs 教程）：ControlNet OpenPose 锁姿态、固定 seed、低 denoise(0.3–0.5) 减闪烁、首尾帧衔接——通用防漂移纪律，与 C60 四维漂移 QA 互补。

## 3. 及时调整建议

> 基线 v4 仍然成立，**不替换本地主线**。但给出三条「今天就该做」的微调（增量而非推翻）：

1. **云快验轨道新增「可灵 Kling 3.0」为并列/优先首选**（对应 C54 升级、新增 C77 类目）：其智能分镜+15s+原生音画+主体参考，比 Seedance 2.5 的「30s 一镜无分镜」更贴合「桃子带情节视频」第一阶段目标，且原生多角色指代已为「下一步」铺路。**建议本周先用 Kling 3.0 出第一条 15s 带情节+配音样片**，与即梦+Seedance 路线对照。不替换 Seedance（即梦分身锚点图工作流 C56/C66 仍独立有价值）。
2. **漫剧装配层把 Toonflow 列为开源首选候选**（新增 C78）：成熟度/star 数远超此前 C62 Pixelle-Video、C75 Stixx/Dify 方案，且本地部署、角色锚定系统是漫剧「不变脸」痛点的工程化解法。Step3 预研直接以 Toonflow 为底座试验，不必另搭 Dify+ComfyUI。
3. **第一步镜头纪律追加一条铁律**（来自 1.5 多源对齐）：**动态提示词只写小幅动作**（眨眼/转头/微抬手/微推），禁大幅跑跳打斗，否则画面崩坏。并入 C43 多镜散文纪律。

**无替换项声明**：LTX-2.5（主线）/ Qwen2512（出图线 A）/ Seedance 2.5（云快验并列）/ Digen（单镜补充）四件套继续作为基线；H3 仍列本地对比/质量补镜轨道；Wan 3.0 / FLUX 3 仅云并列。Sora 2 经第三方横评确认为 **Discontinued**，从「待核实」转为「已退役」，与 C54 一致。
