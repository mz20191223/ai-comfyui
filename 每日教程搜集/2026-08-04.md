### 1.1 🆕【最高优先·视频主线评估】Wan 3.0 已正式发布（Apache 2.0，~April 2026）—— 跨镜一致性 + 原生音画 + 4K + 30s
- 来源：`wan27.org/blog/latest-wan-model` 与 `wan27.org/blog/wan-3-0-everything-we-know`；HuggingFace 权重 `Wan-AI/Wan3.0-*`；kijai `ComfyUI-WanVideoWrapper`（社区已指向 Wan3 封装）。
- **核心要点（正面命中我们「LTX 保 ID 弱、跨镜漂」的痛点，且比 Wan 2.7 更进一步）**：
  - **原生 4K** 单 pass 输出（Wan 2.7 仅 1080p）。
  - **30 秒/镜**（Wan 2.7 ~15s），直接服务「带情节长镜 / 多镜叙事」。
  - **原生音画**：视频内直接生成语音/对白/环境音/音乐（Wan 2.7 仅 R2V 语音参考，不含音乐）→ 一步出带对白成片，省掉我们「LTX 视频 + 单独 TTS + 口型对齐」的链路。
  - **🆕 跨镜强角色一致性**：wan27.org 明确「Strong character consistency across shots —— 直接解决 Wan 2.7 在 r/StableDiffusion / r/comfyui 被吐槽的 'plastic' / 漂移问题」。这正是我们第一步单角色跨镜、下一步多角色、最终漫剧的命脉。
  - **Apache 2.0 开放权重**：1.3B（8GB 消费级可跑）+ 14B（24GB+）；与 Wan 2.7 同架构家族，**提示词/帧控制/参考 conditioning 技能可平移**（wan27 原文：「skills transfer directly to 3.0」）。
  - 生态延伸（July 2026，Apache 2.0）：WanSong（文生音乐 25B）、Wan-Dancer-14B（音乐生舞蹈）、Wan-Streamer（实时流式）。
- **适用**：**潜在替代 LTX 2.3 成为视频主线**（尤其「跨镜一致性 + 原生音画 + 30s + 4K」四项正是我们漫剧终极目标所需）。但须先验证 ComfyUI 节点成熟度 + 本地 14B FP8 在 A10 24GB 的显存可行性。**列为 §4 最高优先新增评估轨道 R，先 1–2 镜对比，不立即替换 LTX**。

### 1.4 🆕【LTX 频道加法升级·高相关第一步】WhatDreamsCost-ComfyUI 节点包（LTX 2.3 I2V/FFLF）
- 来源：`WhatDreamsCost/ComfyUI-*`（X/Reddit 活跃分享，GPL-3.0，Manager 一键装）；解读 `neonframe.ai/comfyui-latest-updates-may-2026-...`。
- **核心要点（直接补全「桃子带情节/对白视频」LTX 编排短板，与 10S-Comfy-nodes 正交）**：
  - **LTX Sequencer**（推荐优于 Keyframer）：真·**FFLF 镜头序列**——支持任意中间帧（首/中/尾帧），秒级而非帧级设关键帧，做**故事分镜序列**零重算帧数；多实例实时同步。
  - **Speech Length Calculator**：**对白时长实时估算**——解析引号内语音段、按语速启发式算时长，连任意文本节点即时反馈，**根治口型错位**（我们 Lovisdotio 编排里「音频时长同步」的现成节点版）。
  - **Multi Image Loader**（内置画廊、自动 resize + LTXVPreprocess、多输出联动）、**Load Audio UI v1.2.4**（拖拽音频/视频+内联裁剪）、**LTX Keyframer**（旧兼容）。
  - 作者称 RTX 40 系上 2–3× 迭代提速；附 `example_workflows/` 含「紧凑 I2V+FFLF+音频」可拖入即用。
- **适用**：**第一步「桃子带情节（含对白/多镜）视频」LTX 编排的缺失拼图**——故事序列 + 对白口型时长目前靠手工/Lovisdotio 拼，现成节点直接补。列为 §4 新增 S。

### 1.5 🆕【LTX 频道加法升级】LTX 2.3 Outpainting / Reframing（IC-LoRA）+ HDR IC-LoRA（LumiVid）
- 来源：官方 `ltx.io` release notes（"Production-grade reframing / Outpaint video beyond frame"）、`docs.ltx.io/open-source-model/advanced-workflows/in-outpainting`（Lightricks 官方 ComfyUI 工作流）、HF `Lightricks/LTX-2.3` IC-LoRA 系列（`in-outpainting-0.9` / `outpaint-v2`）、`oumoumad-ai/LTX-2.3-22b-IC-LoRA-Outpaint`、`runninghub.ai`/`modelscope.cn` 镜像。
- **核心要点（真实、加法，不替换现有）**：
  - **Outpainting / Reframing**：扩展视频画布到原帧之外（横向/纵向/任意组合），保持构图/运动/视觉一致；**典型用法：把横屏桃子成片 reframe 成竖屏 9:16 不裁切**、或场景延展（天/地/背景外扩）。两阶段（base 分辨率生成 → spatial upscaler ×2 → 全分辨率精修），Laplacian 金字塔混合保边界无缝；用 `LTXAddVideoICLoRALoRAAdvanced` 做 mask-aware conditioning。⚠️ 暗场用 gamma 2.0→0.5 往返 trick 解决纯黑 sentinel 歧义（ComfyUI `Color Correct (mtb)` 节点）。
  - **HDR Video Generation IC-LoRA（LumiVid）**：16-bit HDR、完整 ACES 色彩标准、输出 float16 EXR 场景线性，专业后期 re-exposure/调色友好；ComfyUI 开箱 + API video2video。**社媒短可暂不急，留电影级质感升级**（漫剧阶段再用）。
  - **LTX Trainer 统一训练框架（2026-06-17）**：统一视频/音频/跨模态/参考条件训练，含 **agentic 配置生成（用 Claude/LLM 自然语言出 LoRA/IC-LoRA 训练配置）**——直接降低我们「本地训桃子 IC-LoRA（rank 128）」的摩擦（v4 第 8 条长期锁身份）。
- **适用**：LTX 频道的构图/比例灵活性 + 未来电影级画质 + 训练提效；均为叠加，不替换。列为 §4 新增 T。

### 1.6 🆕【下一步/漫剧预备】LiconStudio LTX-2.3 Multiple-Subject-Reference (MSR) V2
- 来源：`comfyui-wiki.com/zh/news/2026-07-11-licon-msr-v2-multi-subject-reference` ；HF `LiconStudio/LTX-2.3-Multiple-Subject-Reference`（Apache 2.0）；插件 `ComfyUI-Licon-MSR`。
- **核心要点**：**多主体参考 LoRA V2**，在 LTX-2.3 上跟踪 **2–5 张参考主体**（人物/物体/场景），解决 V1 的**身份漂移、复杂构图伪影、主题交互不自然**。机制：多张静态参考图 → 伪视频序列（与目标视频同表示空间）→ 参考 token 经**现有自注意力**访问，**无需额外编码器分支**（与我们的 IC-LoRA-Ingredients 单主体参考互补）。
- **适用**：**直接服务「下一步：多角色视频」+ 漫剧多角色叙事**的身份锁。第一步单角色暂不需（我们用 IC-LoRA-Ingredients 单主体即可），但**预标记为漫剧阶段核心工具**。列为 §4 新增 W（预研）。
