## 1. 新发现：教程 / 工具 / 工作流

### 🆕 A. MiniMax H3 —— 首个「开源权重 + 原生立体声音频 + 2K 路径」视频模型（2026-08-03 发布）
- **来源**：ComfyUI Wiki 教程/新闻（comfyui-wiki.com，2026-08-03）、Comfy Org 官方 PR #15224、docs.comfy.org、dev.to 综述
- **核心要点**：
  - 33.1B 单流 omni-transformer，Qwen3-VL-32B 文本编码器；**文本/图像/视频/音频统一上下文**，一次前向同时生成视频 + 32kHz 立体声音频（对白/音效/音乐同pass，非后叠加）。
  - 三种本地模式：**T2V / I2V（首末帧控制）/ R2V（参考到视频，最多 9 图 + 3 视频 + 3 音频，可锁角色/风格/运镜/嗓音）**。
  - **ComfyUI 原生支持 day-0 合并**（v0.30.0+，4 个新节点 + 6 个官方模板），权重在 HuggingFace（MiniMaxAI/MiniMax-H3 与 Comfy-Org/MiniMax-H3）。
  - 本地最小可用包：`fl2va_pruned_int8_convrot`(19.5GB) + `qwen3vl_32b_nvfp4_awq`(14.6GB) + VAEs(5.5GB) ≈ **39.6GB**；官方称经剪枝+int8+动态显存卸载可压到 RTX 3060(12GB) 跑（实质为重度 CPU 卸载、慢）。
  - **2K 由 `H3-Regenerate-2K` 模块产出，该模块暂未开源**，本地仅能验证 768p；2K 需走 MiniMax API。
  - 许可：**MiniMax H3 Community License**——免费非商业；年营收 < 2000 万美元组织可商业使用，需署名。**非完全宽松开源**，商用前须查许可。
- **适用场景**：带对白/音效/配乐的叙事短片（R2V 锁角色 + 原生音频极契合「桃子带情节」）；本地可控迭代。
- **与我们基线的关系**：概念上几乎是「第一步带情节」的理想模型，但本地权重 24GB+ 起，当前 T4 15.9GB 不现实 → 作为**评估轨道**（待更大显存 GPU）。

### 🆕 B. Seedance 2.5 全球上线（2026-07-31 发布 / 8-3 集中报道）—— 单镜验证渠道升级为首选
- **来源**：字节 FORCE 大会(6-23)、今日头条(海淀融媒 8-3)、网易/搜狐/AOL/PRNewswire、ComfyUI_Seedance(GitHub T8mars)、comfyui-seedance(GitHub amortegui84)
- **核心要点**：
  - **单次 30 秒一镜到底**（2.0 为 15 秒）；**多轮延长**可衔接后续镜头并保持人物/场景/节奏连贯，达数分钟。
  - **多模态参考全面升级**：单次最多 **30 图 + 10 视频 + 10 音频**（AOL/PR 稿称最多 50 个参考素材）；含时间戳级编辑、绿幕、clay 渲染、镜头透视控制。
  - **Maya / Blender 插件**（影视级管线）、C2PA 水印 + 可见 AI 标识。
  - 已上线 **即梦(Dreamina)/豆包/Doubao Pro**；**API 经火山引擎 BytePlus ModelArk 即将开放**。
  - ComfyUI 节点已有：`T8mars/ComfyUI_Seedance`（自称官方低价款，31 个示例工作流已真实验证）、`amortegui84/comfyui-seedance`（AnyFast API 桥，含 2.5 Standard/Pro 占位节点）。
- **适用场景**：**单角色带情节短片的快速验证/成片**（30 秒足以讲一个有头有尾的小故事）；多参考锁角色 + 时间戳编辑补镜。
- **与我们基线的关系**：**直接命中「第一步」单镜快速验证渠道**，且显著强于 Digen（时长×2、参考量大、可控编辑）。第三方 API（IP 出境风险 + 成本），定位「验证/补充」不进本地可控主线（与即梦/火山的既有口径一致）。

### 🆕 C. BindWeave（字节开源，ICLR 2026）—— Wan 生态的「主体一致性」正规军
- **来源**：GitHub `bytedance/BindWeave`（ICLR 2026 官方仓库）、fluxbbs 实测、wanx-troopers 指南、RunningHub 对比帖
- **核心要点**：
  - 标题 *Subject-Consistent Video Generation via Cross-Modal Integration*；基于 **Wan 2.1 I2V 14B** 的 **MLLM-DiRA** 架构，把文本中的角色/属性/关系与视觉目标绑定，逐帧保持一致性。
  - **单主体 + 多主体**；**多图参考（人物 + 物体）像素级**；OpenS2V-Eval 得分 57.61（优于部分开源/商业）。
  - ComfyUI 入口：`Kijai/ComfyUI-WanVideoWrapper`（`git switch bindweave` 分支）+ `drozbay/WanExperiments`（原生节点）+ Kijai FP8 GGUF 权重。
  - **与 Lynx 对比**：BindWeave 多图参考(人+物)、高保真、超部分闭源，但不稳定需多次尝试；Lynx 单肖像保真略优但动态差。两者都支持首尾帧无限时长（BindWeave 效果勉强）。
- **适用场景**：**第一步单角色一致性** + **多角色（下一步）**；物体交互（桃子拿道具）。
- **与我们基线的关系**：Wan 2.1 I2V 14B 权重 24GB+，当前 T4 不现实 → **评估轨道**（待更大显存）；概念上其「像素级多图参考」比 LTX IC-LoRA 更强的身份锁潜力。

### 🆕 D. Qwen-Character-2512 LoRA —— 强化出图线 A（Qwen-Image-Edit-2512 角色一致性）
- **来源**：CSDN《Qwen-Image-2512-ComfyUI 操作详解》(blog.csdn.net/weixin_42430341)
- **核心要点**：Qwen-Image-2512 内置工作流集成 `Qwen-Character-2512` LoRA，**单张参考图锁定人物特征（脸型/发型/衣着）**，无需训练即用；`character_strength` 滑块控保留度(0.6 平衡 / 0.9 高一致)；连续 10 张相似度约 87%（FaceNet 比对）。
- **适用场景**：**出图线 A**（桃子角色圣经 / 多角度参考集）低成本增强。
- **与我们基线的关系**：当前主线计划「出图线 A 升 Qwen-Image-Edit-2512」，**叠加此 LoRA 即可强化锁角色**，几乎零额外成本（仅一个 LoRA 文件）。⚠️ 待验证：CSDN 描述的是某镜像内置工作流，需确认该 LoRA 在 HF/Civitai 可独立下载再正式采用。

### 🆕 E. RHSTORY（RunningHub 漫剧工业化系统）—— 预标记「最终：漫剧」目标
- **来源**：新京报/北京新闻(m.bjnews.com.cn)、RunningHub 官方
- **核心要点**：十万字剧本一键导入 → **项目/剧集/场次/镜头 四层结构**；**角色管理系统**（留存多套造型服饰，全剧统一）；720° 全景球场景（任意镜头切换无光影/空间偏差）；自动分镜脚本；单镜头/单章节局部重制；可复用资产库。同期 `rhTV 无限画布`（3D 导演台锁空间逻辑）。
- **适用场景**：**最终漫剧阶段**的工业化生产（多镜头/多角色/连续剧式叙事）。
- **与我们基线的关系**：第三方云平台（非本地），作**漫剧预研 / 方案参考**，待前两步跑通后接入。

### 🆕 F. Wan 3.0 生态补全（Apache 2.0，2026-07）—— 支撑 08-04 评估轨道 R 的上下文
- **来源**：wan27.org、flowith.io
- **核心要点**：随 Wan 3.0 同期开源 `WanSong`(文生音乐 ~25B)、`Wan-Dancer-14B`(音乐生舞蹈)、`Wan-Streamer`(实时流式)。均为 Apache 2.0。
- **适用场景**：若主线转 Wan 3.0，可配套原生音/舞/实时互动；强化「Wan 3.0 原生音画 + 跨镜强一致」作为 LTX 挑战者的完整生态叙事。

## 2. 可行性分析（对照阶段目标与技术基线）

> 当前硬件约束（据历史记忆）：主算力为 **T4 15.9GB** 云实例，LTX 2.3 蒸馏/GGUF + IC-LoRA 恰好可落；**24GB+(A10/4090) 才能跑 Wan/BindWeave/MiniMax H3 本地权重**。

### 第一步：桃子单角色带情节视频（最高优先）
| 方案 | 落到 T4 可行性 | 对「带情节」增益 | 成本/风险 | 结论 |
|---|---|---|---|---|
| **LTX 2.3 主线**（IC-LoRA-Ingredients + draft-then-upscale + 10S Likeness Guide） | ✅ 可落（已规划） | 中（需两阶段采样硬纪律保 ID） | 低 | **维持本地可控主线** |
| **出图线 A 升 2512 + Qwen-Character-2512 LoRA** | ✅ 可落（仅加一个 LoRA） | 高（锁角色出图更稳） | 极低 | **建议采纳（D）** |
| **Seedance 2.5（云 API）作单镜验证** | ✅（云端，不占本地显存） | 高（30s 一镜到底 + 时间戳编辑） | 中（成本 + IP 出境） | **建议升为单镜验证首选，替代/补充 Digen（B）** |
| **MiniMax H3（本地）** | ❌ T4 不现实（≈40GB） | 极高（R2V 锁角色 + 原生音频） | 高（需换大显存实例） | **评估轨道，待更大 GPU** |
| **BindWeave（本地 Wan）** | ❌ T4 不现实（24GB+） | 高（像素级多图参考） | 高（需换大显存） | **评估轨道，待更大 GPU** |
| **Digen（既有）** | ✅ | 低-中（单镜） | 低 | **降级为备份验证渠道** |

**收益判断**：第一步当下最值得做的两件事——(1) 出图线 A 加 Qwen-Character-2512 LoRA（几乎零成本强化锁角色）；(2) 单镜验证从 Digen 升级到 Seedance 2.5（30 秒带情节一镜到底，远超 Digen）。本地可控成片仍靠 LTX 2.3 主线。

### 下一步：多角色
- **BindWeave / LTX MSR（runcomfy 多主体 IC-LoRA）/ Wan 3.0 原生跨镜一致** 均为候选；当前 T4 仅 LTX MSR 可能勉强（需测），其余待大显存。预标记评估，不立即投入。

### 最终：漫剧
- **RHSTORY / rhTV（E）**、08-04 的 MSR V2(W) + 编辑技巧(X) 已预标记。本地路线仍靠 LTX 主线 + 剪辑拼接掩 ID 漂移。

## 3. 及时调整建议

1. **单镜验证渠道：建议把 Digen 升级为 Seedance 2.5（云）作为第一步首选快速验证**。理由：Seedance 2.5 单次 30 秒一镜到底 + 多轮延长 + 最多 30 图/10 视频/10 音频参考 + 时间戳编辑，完胜 Digen 的单镜能力；Digen 降为备份。**替换的是「基线里 Digen 单镜头快速验证」这一环**，本地 LTX 主线与 Qwen 出图线不动。风险：第三方 API 的 IP 出境与成本，故仅作验证/补充、不进可控主线（与即梦/火山既有口径一致）。

2. **出图线 A：建议叠加 Qwen-Character-2512 LoRA**。替换/增强的是「Qwen-Image-Edit-2512 锁角色出图」这一步——在既有升 2512 计划上**加一个角色一致性 LoRA**，零额外基础设施成本进一步稳住桃子脸/衣。需先确认该 LoRA 在 HF/Civitai 可独立下载（CSDN 仅见镜像内置）。

3. **本地可控主线：暂不替换 LTX 2.3**。原因：当前 T4 15.9GB 下，MiniMax H3(≈40GB) 与 BindWeave(Wan 14B, 24GB+) 均无法本地跑；LTX 2.3 蒸馏 + IC-LoRA 是唯一契合显存的本地可控方案。**若用户后续换 A10/4090(24GB) 及以上实例，则 MiniMax H3（原生音频带情节）与 BindWeave（像素级多图参考）应作为主线潜在替代/并行评估**，优先级高于 Wan 3.0（H3 已带原生音频，更贴「带情节」）。

4. **漫剧预研：建议把 RHSTORY/rhTV 纳入最终阶段方案库**（第三方云，作工业化生产参考），不现在投入。
