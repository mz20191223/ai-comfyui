## 1. 新发现：教程 / 工具 / 工作流

### 🆕 A. ComfyUI-Novel-Director（GitHub，MIT 风格自定义节点包）—— 直接命中「下一步：多角色」与「最终：漫剧」
- **来源**：https://github.com/Work-Fisher/ComfyUI-Novel-Director （GitHub 实抓 README 确认）
- **核心要点（README 原文要点）**：
  - **多角色统筹 Casting System**：单节点 **6 人选角**，可串联无限扩展；图像与角色名绑定。
  - **智能脚本解析**：喂入 LLM（ChatGPT/DeepSeek）生成的 **JSON 脚本**，自动切分 **Audio Script（台词/角色名/音色 Instruct）/ Visual Storyboard（分镜画面提示词）/ Video Prompts（运镜/动态）**。
  - **自动流式处理（Scene Iterator）**：自动对齐文本/语音/画面/运镜，实现「一键生成多集」。
  - **高级 TTS 适配**：自动为台词加 `角色名:` 前缀（适配 Qwen-TTS）；输出角色字典供 GPT-SoVITS 建音色库；生成极简角色设定表。
  - **精准时序控制**：按音频时长自动算视频帧数 + Buffer Frames 缓冲帧；全部片段生成后**自动合并为 `Final_Movie.mp4`**，并可回流 ComfyUI 二次处理。
- **适用场景**：**多角色短剧 / 有声小说 / 动态漫**的「脚本→分镜→配音→合并」一体化编排层。
- **与我们基线的关系**：它是一个**编排/管线层**，底层仍调用我们的出图线 A（Qwen）与视频线（L2 主线 LTX / 或 H3 / Seedance）。本身不解决单角色一致性，但把「多角色分镜 + 音画对齐 + 自动批量 + 合并」工程化，**正是「下一步：多角色」与「最终：漫剧」预研的最佳骨架**。⚠️ 当前 T4 上它只是编排，**真正出片仍受 LTX/H3 显存约束**，故列为下一阶段预研，不进 Step 1。

### 🆕 B. MiniMax H3 社区量化权重已确认落地（Aug 3，多仓），但 T4 15.9GB 无法本地跑
- **来源**：
  - 聚合：https://comfyui-wiki.com/en/news/2026-08-03-minimax-h3-community-quants
  - 集合仓：https://huggingface.co/Abiray/Minimax-H3-nvfp4-INT4-INT8-Convrot
  - GGUF 仓：https://huggingface.co/joeygambino/MiniMax-H3-GGUF ｜ https://huggingface.co/realrebelai/MiniMax-H3_GGUFs
  - 官方：https://huggingface.co/Comfy-Org/MiniMax-H3 ｜ https://sd114.wiki/33481.html
- **核心要点（精确化，已实抓核验）**：
  - **开源当天（Aug 3）即现 4 个社区量化仓**：GGUF Q2–Q5、pruned INT4/INT8、NVFP4，多数带 ComfyUI 工作流。
  - **按 GPU 选文件指南（Abiray 仓官方）**：
    - 16GB 卡（RTX 4070 Ti Super / 4080，**Ampere/Blackwell**）→ GGUF Q3/Q4 或 pruned **INT4（~11.3GB）/ mixed INT4-INT8（~15.5GB）** + **INT4 文本编码器（~15GB）**。
    - 24GB 卡（RTX 3090 / 4090）→ pruned **INT8（~21GB）** + INT8 文本编码器（~27GB）。
    - **Blackwell 专属（RTX 5090 / PRO 6000）** → **NVFP4（12.5GB）** + NVFP4 AWQ 文本编码器。
  - **GGUF 仓实参（joeygambino）**：fl2va/ref2va Q4_0 ≈ **19.9GB（16GB 卡需溢出流）**；Q5_1 ≈ 25.9GB（24–32GB 卡）。需 ComfyUI-GGUF + **ComfyUI-H3-Multishot v1.5.2+** 架构补丁 + ComfyUI 0.30.0+。
  - **realrebelai 仓**：FL2VA/REF2VA Q3_K_M **14.51GB**、Q4_K_M 18.50GB；文本编码器 Q2_K **7.91GB**。
  - **所有人都必须下两个 VAE**：`minimax_h3_audio_vae_fp32` + `minimax_h3_video_vae_fp16`。
  - **⚠️ 许可地域排除（延续 08-05）**：MiniMax H3 Community License 排除 **美国/欧盟/英国/韩国** 商用 —— 部署前须确认合规。
- **与我们基线的关系（关键硬件真理）**：**T4 = 15.9GB Turing 架构**，不在任何 H3 量化适配档（最小可行 combo ≈ 扩散 11.3GB + 文本编码器 7.9GB ≈ 19.2GB，且文本编码器最小也 7.9GB，叠加 VAE/激活/上下文必超 15.9GB）。**结论：H3 本地权重对 T4 不可行，属 ≥16GB(Ampere/Blackwell) 评估轨道**。这与 08-05/08-07 的判断一致并被精确量化证实。
- **补偿路径不变**：H3-**API**（768p ¥0.23/s，见 08-07 §C）仍是桃子带情节短片的**廉价云端验证**首选，本地主线待换大显存再评。

### 🆕 C. MAGI-2 Preview（Sand.ai）开源 —— 行业里程碑，但本地完全不可及（仅作信号）

  - **成本口径澄清（重要，避免误读）**：报道「10 秒 1080P 约 0.5 元」是 **Sand.ai 按 8 卡 H100 月租折算的「自有集群推理成本」**，**并非面向用户的零售 API 价格**，也不代表我们能以 ¥0.5/10s 买到。属厂商成本宣传，不可当作可采购单价。

### 🆕 D. LTX 2.3 INT8 V1.6 整合包 —— 宣称 8GB 可跑，但「优先 Ampere（RTX 30XX）」，T4（Turing）需实测
- **来源**：
  - https://kwkr.cn/news/47732.html ｜ https://blog.csdn.net/weixin_34150830/article/details/91470114 ｜ https://blog.csdn.net/benbenqingqing1/article/details/83209203
